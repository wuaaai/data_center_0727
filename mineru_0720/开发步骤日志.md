# 开发步骤日志

## 需求概述

1. **手动修改 Word + 重新入库**（方案A）：下载带分块标记的 DOCX → Word 编辑 → 上传替换 → 重新入库
2. **分类展示/筛选**：统计栏的"总计/排队/处理中/已完成/失败/已入库"可点击，筛选对应文件
3. **可嵌入设计**：支持 `?embed=1` 参数，去掉头部/底部，适合作为另一个后台管理系统的 iframe 页面

## 改动摘要

### 后端新增 API

| 端点 | 功能 |
|------|------|
| `POST /api/jobs/{job_id}/replace` | 上传修改版 DOCX 替换原输出。completed/ingested → completed |
| `POST /api/direct-upload` | 上传手工 DOCX，跳过 MinerU 处理，直接创建 completed 任务 |

### 后端修改

| 文件 | 改动 |
|------|------|
| `state_manager.py` | `create_job()` 新增 `modified_at` / `modify_count` 字段；新增 `replace_job_output()` |
| `routes/ingest.py` | 入库状态门从 `!= "completed"` → `not in ("completed", "ingested")` |
| `routes/jobs.py` | 页面路由支持 `?status=` 筛选和 `?embed=1` 嵌入模式 |
| `server.py` | 注册 replace 路由 |

### 前端新增

| 功能 | 说明 |
|------|------|
| 可点击统计栏 | "总计/排队/处理中/已完成/失败/已入库" 每个都是可点击链接，筛选对应状态。当前激活项高亮。 |
| 替换按钮 | completed/ingested 的 job 卡片和详情页都有"替换"按钮，点击选文件自动上传 |
| 直接上传栏 | 页面顶部绿色栏，上传手工 DOCX 跳过 MinerU 处理 |
| embed 模式 | URL 加 `?embed=1`，隐藏 header 和上传区域，适合 iframe 嵌入 |
| 修改计数 | 替换后在卡片上显示"已修改 N 次" |

### 状态机

```
uploaded → queued → processing → completed → ingesting → ingested
                ↓                     ↑                      ↓
              failed           (replace)              (replace)
                                   ↑                      ↓
                               completed ←───────────────┘
                                               (也可直接重新入库)
```
