## 二、解决方案架构

### 2.1 核心思路：流水线 + 并行 + 弹性扩缩

```
                      批量上传层
    ┌──────────────────────┼──────────────────────┐
    │ 文件夹拖拽上传        │ 批量选择文件          │ 远程目录扫描         │
    │ (前端拖拽一个文件夹)   │ (Ctrl+A 全选)        │ (服务器端扫描目录)    │
    └──────────┬───────────┴──────────┬───────────┘
               │                      │
               ▼                      ▼
    ┌─────────────────────────────────────────────┐
    │           ① 上传管道 (Upload Pipeline)        │
    │  ┌─────────┐  ┌─────────┐  ┌─────────┐      │
    │  │ 分片上传  │→│ 秒传去重  │→│ 并发写入  │      │
    │  │ 10线程   │  │ MD5检测  │  │ 异步I/O  │      │
    │  └─────────┘  └─────────┘  └─────────┘      │
    │  吞吐: 10-20 文件/秒 (小文件)                 │
    └────────────────────┬────────────────────────┘
                         │
                         ▼
    ┌─────────────────────────────────────────────┐
    │         ② 调度层 (Smart Scheduler)            │
    │  ┌──────────┐  ┌──────────┐  ┌──────────┐   │
    │  │ 优先级队列│  │ 动态并发  │  │ 失败重试  │   │
    │  │ 3级优先级 │  │ 1-8 worker│  │ 指数退避  │   │
    │  └──────────┘  └──────────┘  └──────────┘   │
    └────────────────────┬────────────────────────┘
                         │
                         ▼
    ┌─────────────────────────────────────────────┐
    │          ③ 解析层 (MinerU Workers)            │
    │  ┌──────────┐  ┌──────────┐  ┌──────────┐   │
    │  │ Worker 1 │  │ Worker 2 │  │ Worker N │   │
    │  │ GPU 0    │  │ GPU 0    │  │ GPU 1    │   │
    │  └──────────┘  └──────────┘  └──────────┘   │
    │  并发: 2-8 (可配置), GPU 负载均衡            │
    └────────────────────┬────────────────────────┘
                         │
                         ▼
    ┌─────────────────────────────────────────────┐
    │         ④ 入库层 (Batch Ingest)               │
    │  ┌──────────┐  ┌──────────┐  ┌──────────┐   │
    │  │ 批量切片  │→│ 批量Embed │→│ COPY写入  │   │
    │  │ 并行读取  │  │ 32条/批   │  │ PostgreSQL│   │
    │  └──────────┘  └──────────┘  └──────────┘   │
    │  吞吐: 500-2000 切片/秒                      │
    └─────────────────────────────────────────────┘
```

### 2.2 设计原则

1. **流水线不等待** — 上传 → 解析 → 入库 三个阶段互相独立，文件上传完立即进入解析队列
2. **弹性并发** — 根据系统 CPU/GPU/内存自动调整 worker 数量
3. **断点续传** — 批量任务中途断掉不丢失进度，重启后从断点继续
4. **可视化进度** — 大批量任务有独立进度面板：总文件数/已完成/失败/速度/预估剩余时间

#### 3.1.3 分片上传 (大文件)

| 特性 | 说明 |
|------|------|
| 分片大小 | 默认 10MB/片，可配置 |
| 并发分片 | 3-5 片同时上传（避免浏览器连接数限制） |
| 断点续传 | localStorage + 服务端临时文件记录已上传分片 |
| 超时重试 | 单分片失败自动重试 3 次 |

#### 3.1.4 秒传去重

- 上传前计算文件 MD5
- 查询服务端已上传列表
- 相同 MD5 且处理成功 → 直接跳过，"秒传成功"
- 相同 MD5 但处理失败 → 重新处理

### 3.2 智能调度器 (Smart Scheduler) ⭐ 亮点

#### 3.2.1 三级优先级

| 优先级 | 来源 | 示例 |
|--------|------|------|
| 🔴 高 | 前端用户实时上传、手动触发 | 业务人员当场需要结果 |
| 🟡 中 | 批量导入任务 | 地市数据一次性导入 |
| 🟢 低 | 后台定时任务、重新处理 | 夜间批量重处理失败文件 |

#### 3.2.2 动态并发

```
Worker Count = min(
    MAX_WORKERS,
    max(1, floor(CPU_CORES * 0.5)),
    优先级调整: 高优 +2, 低优 -1,
    队列积压调整: 积压 > 100 → +1
)
```

**资源感知：**
- 监控 GPU 显存使用率，超过 80% 则不新增 worker
- 监控系统内存，低于 2GB 空闲时降速
- 监控 Embedding API 响应时间，超过 5 秒时降低入库批次大小

#### 3.2.3 失败重试策略

```
重试次数: 最多 3 次
退避策略: 指数退避 (1min → 5min → 15min)
可重试错误: 网络超时、API 限流、GPU OOM
不可重试: 文件损坏、格式不支持、模型加载失败
```

**失败文件隔离：**
- 失败文件自动移到"待处理"列表
- 不阻塞队列中后续文件的处理
- 批量任务完成后展示失败清单及原因

### 3.4 批量入库优化 ⭐ 亮点

#### 3.4.1 当前 vs 优化

| 环节 | 当前实现 | 优化方案 | 提升 |
|------|---------|---------|------|
| DOCX 读取 | 单个读取 | 并行读取 4 个 | 4x |
| Embedding 调用 | 逐条发送 | 批量发送 32条/批 | 32x |
| PostgreSQL 写入 | 逐条 INSERT | COPY 批量导入 | 50x+ |
| 入库锁 | 全局互斥锁 | 知识库级别锁 | N 倍 |

#### 3.4.2 批量 Embedding

```python
# 当前: 逐条发送
for text in texts:
    resp = requests.post(api_url, json=[text])  # N 次 HTTP 请求

# 优化: 批量发送
BATCH_SIZE = 32
for i in range(0, len(texts), BATCH_SIZE):
    batch = texts[i:i+BATCH_SIZE]
    resp = requests.post(api_url, json=batch)  # N/32 次 HTTP 请求
```

#### 3.4.3 COPY 批量写入

```python
# 当前: 逐条 INSERT
for text, emb, meta in zip(texts, embeddings, metadatas):
    cur.execute("INSERT INTO ... VALUES (%s, %s, %s)", (text, str(emb), json.dumps(meta)))

# 优化: StringIO + COPY
import io
buf = io.StringIO()
for text, emb, meta in zip(texts, embeddings, metadatas):
    buf.write(f"{text}\t{emb}\t{json.dumps(meta)}\n")
buf.seek(0)
cur.copy_from(buf, "parent_child_db_1024", columns=("c_document", "c_embedding", "c_metadata"))
```
