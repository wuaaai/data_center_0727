# 地区权限分配方案 — 产品设计 & 用户体验优化

> 版本: v1.0 | 日期: 2026-07-27 | 优先级: P0 核心体验

---

## 一、问题场景

### 1.1 用户痛点

财政局管理员上传 200 份各地市文件，面临三个核心难题：

1. **文件是混在一起的** — 邯郸、石家庄、保定...各地的预算报告混在一批里上传
2. **不记得哪个文件该分给哪个地市** — 文件名往往不含地市信息，需要打开看内容才能判断
3. **当前只能逐个分配** — 每个文件都要在下拉菜单中选地区，200 份文件需要 200 次下拉选择 + 200 次点击

### 1.2 当前系统的问题

```
上传弹窗:
┌─ file1.pdf  [石家庄市 ▼]  ← 逐一手动下拉选择
├─ file2.pdf  [邯郸市 ▼]
├─ file3.pdf  [保定市 ▼]
├─ file4.pdf  [选择地区*]  ← 必须每个都选，不然报错
├─ file5.pdf  [选择地区*]
├─ ... (还有 195 条)
└─ [开始上传]  ← 前面漏选一个都不行
```

**用户操作量 = N 次下拉选择 + N 次点击 = 200 次 × 2 = 400 次操作**

---

## 二、产品设计方案：4 层递进分配

### 2.1 核心设计原则

**让用户从"不得不逐个选"变成"自然归类后再上传"，层层递进，逐级减少工作量。**

```
第零层: 零操作 — 默认值兜底（同批次统一分配）
  ↓ 不够精准？
第一层: 少操作 — 按文件名规则自动匹配
  ↓ 还有漏网之鱼？
第二层: 直观操作 — 文件分组区，拖拽分配
  ↓ 还有特殊文件？
第三层: 精准操作 — 关键词搜索 + 智能建议 + 逐文件微调
```

---

### 2.2 第零层：默认值兜底（零操作）

**设计：** 整个批次设置一个默认地区，所有未单独指定的文件自动继承。

```
┌── 批量文档上传 ─────────────────────────────────┐
│                                                  │
│   📁 已选择 200 个文件 / 总计 1.8 GB              │
│                                                  │
│   默认地区: [河北省本级 ▼]     ← 不改就不需要操作  │
│   📌 所有文件将默认分配到此地区                    │
│                                                  │
│   ☑ 允许单独覆盖某些文件的地区设置                │
│                                                  │
│   [开始上传]                                     │
└──────────────────────────────────────────────────┘
```

**效果：** 如果 200 份全是省本级文件 → 零操作，直接上传。

---

### 2.3 第一层：文件名规则自动匹配（少量操作）⭐ 亮点

**设计：** 系统自动分析文件名，用关键词匹配规则建议地区。

```
┌── 智能匹配结果 ─────────────────────────────────┐
│                                                  │
│  ✅ 已自动匹配 183 个文件 / 200 个文件            │
│  ⚠ 未匹配 17 个文件，需要手动指定                 │
│                                                  │
│  匹配规则:                                       │
│  ┌─────────────────────────────────────────────┐ │
│  │ 匹配规则                  │ 匹配数 │ 样例    │ │
│  │ 文件名包含 "石家庄" →       │ 31     │ 石家庄市..│ │
│  │ 文件名包含 "邯郸" →         │ 28     │ 邯郸市预..│ │
│  │ 文件名包含 "sjz" → (拼音)   │ 12     │ sjz_202..│ │
│  │ 文件名包含 "130100" → (编码)│ 8      │ 130100_.│ │
│  │ ...                        │        │          │ │
│  └─────────────────────────────────────────────┘ │
│                                                  │
│  未匹配文件 (17):                                 │
│  ├── 预算报告_2026.pdf         → [手动指定 ▼]    │
│  ├── 决算汇总表_final.docx     → [手动指定 ▼]    │
│  └── ... (展开全部 17 条)                        │
│                                                  │
│  [接受全部匹配] [逐个审核匹配结果]                 │
└──────────────────────────────────────────────────┘
```

**规则引擎支持的匹配方式：**

| 匹配类型 | 示例 | 说明 |
|----------|------|------|
| 中文全称 | `石家庄市` | 精确匹配 |
| 中文简称 | `石家庄`、`石市` | 模糊匹配 |
| 拼音 | `sjz`、`shijiazhuang` | 不区分大小写 |
| 区划编码 | `130100`、`130100000` | 7 位或 9 位 |
| 目录名 | `石家庄/`、`130100_预算/` | 目录扫描时自动提取 |

**规则管理：** 管理员可自定义添加匹配规则

```
┌── 管理匹配规则 ─────────────────────────────────┐
│                                                  │
│  [新增规则]                                      │
│  关键词: [邯郸      ]                            │
│  匹配方式: [包含 ▼]  (包含/精确/正则)            │
│  目标地区: [邯郸市 ▼]                            │
│  [保存] [取消]                                   │
│                                                  │
│  已有规则:                                       │
│  ┌─────────────────────────────────────────────┐ │
│  │ 关键词      │ 方式 │ 目标地区   │ 操作       │ │
│  │ 石家庄      │ 包含 │ 石家庄市    │ [编辑][删除]│ │
│  │ sjz        │ 包含 │ 石家庄市    │ [编辑][删除]│ │
│  │ 邯郸/HD    │ 包含 │ 邯郸市      │ [编辑][删除]│ │
│  │ ...        │      │            │            │ │
│  └─────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────┘
```

```

│                                                                    │

│                                                                    │
│   ┌──────────────┐ ┌──────────────┐ ┌──────────────┐             │

│   │  ─────────── │ │  ─────────── │ │  ─────────── │             │

│   │              │ │              │ │              │             │
```

**交互体验：**

- 快捷操作：全选未分类 → 一键分配到指定地区

### 2.6 目录扫描 + 自动分配（最省力）⭐ 亮点

**设计：** 如果用户已经把文件按地市分好文件夹，扫描时自动按目录结构分配：

```
服务器目录:
D:\待处理文档\
  ├── 石家庄市\
  │   ├── 预算报告_2026.pdf
  │   └── 执行报告_2025.pdf
  ├── 邯郸市\
  │   ├── 计划解读_2026.docx
  │   └── 预算说明_2026.pdf
  ├── 保定市\
  │   └── ...
  └── 省本级\
      └── ...

扫描结果:
  ✅ 石家庄市/ → 31 个文件 → 自动分配给"石家庄市"
  ✅ 邯郸市/   → 28 个文件 → 自动分配给"邯郸市"
  ✅ 保定市/   → 22 个文件 → 自动分配给"保定市"
  ✅ 省本级/   → 12 个文件 → 自动分配给"河北省本级"

  一键确认 → 无需任何手动分配
```

**支持两种目录组织方式：**

| 目录名模式 | 示例 | 映射到 |
|-----------|------|--------|
| 按地市中文名 | `石家庄市/`、`邯郸市/` | 对应行政区划 |
| 按区划编码 | `130100/`、`130400/` | 自动解析编码 |

## 三、分配流程对比

### 3.1 当前流程 vs 优化后流程

```
当前流程（200 个文件）:
1. 逐个添加文件 → 200 次点击
2. 逐个下拉选择地区 → 200 次下拉
3. 逐个确认上传 → 200 次确认
────────────────────────────────
  总计: ~600 次操作, 耗时 20-30 分钟

优化后流程（200 个文件，最佳情况）:
1. 目录扫描 → 1 次点击
2. 自动按子目录分配 → 0 次操作
3. 确认 → 1 次点击
────────────────────────────────
  总计: 2 次操作, 耗时 10 秒

优化后流程（200 个文件，一般情况）:
1. 拖拽上传 200 个文件 → 1 次拖拽
2. 文件名规则自动匹配 → 183 个已分配, 0 次操作
3. 未匹配 17 个 → 拖拽分批处理 ~5 次拖拽
4. 确认 → 1 次点击
────────────────────────────────
  总计: ~7 次操作, 耗时 1-2 分钟
```

### 3.2 效率提升

| 场景 | 当前操作数 | 优化后操作数 | 提升 |
|------|----------|------------|------|
| 全为同一地区 | 400 次 | **2 次** | 200x |
| 混合地区, 文件有规律命名 | 400 次 | **~10 次** | 40x |
| 混合地区, 文件无规律 | 400 次 | **~50 次** | 8x |
| 目录已分好 | - | **2 次** | N/A |

## 四、后端支持

### 4.1 新增 API

| 方法 | URL | 说明 |
|------|-----|------|
| GET | `/ragdata/region-match-rules` | 获取匹配规则列表 |
| POST | `/ragdata/region-match-rules` | 新建匹配规则 |
| PUT | `/ragdata/region-match-rules/{id}` | 编辑匹配规则 |
| DELETE | `/ragdata/region-match-rules/{id}` | 删除匹配规则 |
| POST | `/ragdata/upload/preview-allocation` | 预览文件→地区的自动匹配结果 |
| POST | `/ragdata/upload/batch-allocate` | 批量应用分配结果 |

**`preview-allocation` 请求：**
```json
{
  "file_names": ["石家庄市预算报告.pdf", "邯郸市计划解读.docx", "unknown_file.pdf"],
  "use_rules": true,
  "use_ai_suggest": true
}
```
**响应：**
```json
{
  "matched": 2,
  "unmatched": 1,
  "allocations": [
    {"filename": "石家庄市预算报告.pdf", "region_code": "1301000", "region_name": "石家庄市", "method": "rule:包含'石家庄'"},
    {"filename": "邯郸市计划解读.docx", "region_code": "1304000", "region_name": "邯郸市", "method": "rule:包含'邯郸'"},
    {"filename": "unknown_file.pdf", "region_code": null, "method": "manual_required"}
  ]
}
```

### 4.2 匹配规则存储

```sql
CREATE TABLE region_match_rules (
    id          SERIAL PRIMARY KEY,
    keyword     VARCHAR(100) NOT NULL,
    match_type  VARCHAR(20) DEFAULT 'contains',  -- contains | exact | regex
    region_code VARCHAR(20) NOT NULL,
    priority    INTEGER DEFAULT 0,
    created_at  TIMESTAMP DEFAULT NOW()
);
```
