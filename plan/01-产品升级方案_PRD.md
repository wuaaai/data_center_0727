# 知识库数据管理 — 产品升级方案

> 版本: v1.0 | 日期: 2026-07-27 | 作者: 产品/开发团队

---

## 一、背景与目标

### 1.1 当前现状

当前系统是单知识库模式：所有文档的向量切片存放在一张 `parent_child_db_1024` 表中，通过 `source` 字段区分文档来源，通过 `region_code` 区分地区权限。

**核心痛点：**
- 无法创建多个知识库，所有文档混在一起
- 文档只有"入库/出库"两种状态，无法暂时停用
- 知识库没有启用/禁用开关
- 文档元数据信息展示不足
- 缺少产品差异化亮点

### 1.2 升级目标

将"单表文档管理"升级为"多知识库平台"，支持：
- 多知识库创建、管理、切换
- 文档级别和知识库级别的启用/禁用
- 丰富的元数据管理和可视化
- 智能检索测试、质量评估等差异化功能

### 1.3 用户角色

| 角色 | 描述 | 权限 |
|------|------|------|
| 管理员 | 系统运维人员 | 全部权限：创建知识库、管理文档、配置权限 |
| 知识库维护者 | 各部门数据负责人 | 管理所属知识库的文档上传/入库/编辑 |
| 普通用户 | 业务人员 | 检索召回（只读） |

## 三、核心功能详细设计

### 3.1 多知识库管理 (P0)

**用例：** 财政局有"预算管理"、"社保资金"、"教育经费"三个业务域，需要分别建立知识库，各自管理。

**功能点：**

| 编号 | 功能 | 描述 |
|------|------|------|
| KB-01 | 创建知识库 | 弹窗输入名称、描述，自动生成 ID |
| KB-02 | 编辑知识库 | 修改名称、描述 |
| KB-03 | 删除知识库 | 需确认，同时清理下属所有文档切片 |
| KB-04 | 知识库列表 | 卡片或表格展示所有知识库及其统计 |
| KB-05 | 知识库切换 | 顶部下拉选择当前操作的知识库 |
| KB-06 | 启用/禁用 | 开关按钮，停用后检索召回自动跳过 |

**交互流程：**

```
[首页知识库选择器] → 选择目标知识库
  → 文档列表自动切换为该知识库的文档
  → 上传文档时自动归属当前知识库
  → 仪表盘数据按知识库过滤
```

### 3.2 文档启用/禁用 (P0)

**用例：** 某政策文件已过期，但不想删除，先禁用保留数据，需要时再启用。

**功能点：**

| 编号 | 功能 | 描述 |
|------|------|------|
| DOC-01 | 单文档切换 | 表格操作列增加 switch 开关 |
| DOC-02 | 批量切换 | 勾选多个文档 → 一键启用/禁用 |
| DOC-03 | 状态筛选 | 筛选栏增加"已启用/已禁用"选项 |
| DOC-04 | 检索过滤 | 召回时自动过滤 `enabled=false` 的切片 |

**状态变更逻辑：**
- 禁用 → 不删除向量数据，仅更新 `c_metadata.enabled = false`
- 启用 → 恢复为 `true`，立即在检索中生效
- 出库 → 删除全部切片（与禁用不同）

### 3.3 知识库启用/禁用 (P0)

**用例：** "测试知识库"不再使用，停用后避免误检索。

**功能点：**

| 编号 | 功能 | 描述 |
|------|------|------|
| KB-E01 | 切换开关 | 知识库卡片/详情页的启用/禁用按钮 |
| KB-E02 | 批量影响 | 停用知识库 = 该知识库下所有文档检索自动跳过 |
| KB-E03 | 状态标签 | 列表中显示"运行中/已停用"标签 |

### 3.4 文档元数据详情 (P0)

**用例：** 管理员想了解某文档的完整信息：何时上传、处理耗时、切片分布、质量评分。

**功能点：**

| 编号 | 功能 | 描述 |
|------|------|------|
| META-01 | 元数据弹窗 | 点击文档名或详情按钮 → 弹出完整 metadata 面板 |
| META-02 | 基础信息 | 文件名、大小、格式、上传时间、入库时间 |
| META-03 | 处理信息 | 处理耗时、切片数量、分块策略、处理状态 |
| META-04 | 权限信息 | region_code、region_name、知识库归属 |
| META-05 | 标签管理 | 查看/添加/删除标签 |
| META-06 | 编辑保存 | 支持修改标签、所属知识库等可编辑字段 |

### 3.5 智能检索测试台 (P1) ⭐ 亮点

**用例：** 管理员入库了一份政策文档，想验证用户搜索时能否正确召回。

**功能点：**

| 编号 | 功能 | 描述 |
|------|------|------|
| SEARCH-01 | 搜索框 | 输入查询文本 → 实时返回 Top-K 结果 |
| SEARCH-02 | 结果展示 | 卡片列表：文档名、片段内容、相似度分数、高亮匹配词 |
| SEARCH-03 | 参数调节 | 滑块设置 Top-K (1-50)、相似度阈值 (0-1) |
| SEARCH-04 | 过滤器 | 按知识库、文档、enabled 状态、region_code 过滤 |
| SEARCH-05 | 对比模式 | 并排显示"启用前 vs 启用后"的检索差异 |
| SEARCH-06 | 一键跳转 | 点击结果可跳转到对应文档的元数据详情 |

**交互设计：**
```
┌─────────────────────────────────────────────┐
│ 🔍 检索测试台                                │
│ ┌─────────────────────────────────┐ [搜索]  │
│ │ 输入查询文本...                   │         │
│ └─────────────────────────────────┘         │
│ Top-K: [10] 阈值: [0.7]  知识库: [全部 ▼]   │
├─────────────────────────────────────────────┤
│ 结果 1 │ 文档名: xxx    相似度: 0.92 ★★★★★ │
│        │ ...文本片段高亮...                  │
│ 结果 2 │ 文档名: yyy    相似度: 0.85 ★★★★  │
│        │ ...文本片段高亮...                  │
└─────────────────────────────────────────────┘
```

### 3.6 文档标签系统 (P1) ⭐ 亮点

**用例：** 给文档打上 `【预算】` `【2026】` `【中央文件】` 等标签，后续按标签快速筛选。

**功能点：**

| 编号 | 功能 | 描述 |
|------|------|------|
| TAG-01 | 系统自动标签 | 入库时根据内容自动标记：文件类型、年份、页数范围 |
| TAG-02 | 手动标签 | 元数据弹窗中自由添加/删除标签 |
| TAG-03 | 标签云 | 知识库页面侧栏展示标签云（按使用频率排序） |
| TAG-04 | 标签筛选 | 点击标签 → 过滤文档列表（支持多选交集/并集） |
| TAG-05 | 标签建议 | 输入标签时下拉提示已有相似标签 |

**标签存储：** `c_metadata.tags` 字段，JSON 数组 `["预算", "2026", "中央文件"]`

### 3.7 批量操作增强 (P1)

| 编号 | 功能 | 描述 |
|------|------|------|
| BATCH-01 | 批量启用/禁用 | 勾选 → 点击"启用选中"或"禁用选中" |
| BATCH-02 | 批量修改地区 | 勾选 → 选择新地区 → 一键更新 |
| BATCH-03 | 批量修改标签 | 勾选 → 追加/覆盖标签 |
| BATCH-04 | 批量迁移 | 将文档从一个知识库移动到另一个 |

### 3.8 知识库仪表盘 (P2) ⭐ 亮点

**用例：** 管理员打开首页，一览所有知识库的运行状态和关键指标。

**功能点：**

| 编号 | 功能 | 描述 |
|------|------|------|
| DASH-01 | 知识库概览卡片 | 文档数、切片总数、总字符量、最后更新 |
| DASH-02 | 文档类型分布 | 饼图：PDF/DOCX/直传 占比 |
| DASH-03 | 切片质量分布 | 柱状图：文档切片数分布，高亮碎片化异常 |
| DASH-04 | 近期动态 | 时间线：最近 10 条入库/出库/编辑记录 |
| DASH-05 | 存储估算 | 向量存储空间：1024维 × 切片数 × 4字节 |
| DASH-06 | 标签分布 | 横向柱状图：TOP 10 标签 |

### 3.9 文档质量评分 (P2)

**评分维度：**

| 指标 | 权重 | 计算方式 |
|------|------|---------|
| 切片完整度 | 30% | 平均切片长度 / 预期长度 (500字符) |
| 嵌入覆盖度 | 25% | 有有效向量切片的占比 |
| 区域标签覆盖 | 20% | region_code ≠ "000000" 的比例 |
| 自定义标签数 | 15% | 标签数量 ≥ 2 个为满分 |
| 内容完整度 | 10% | 文档页数是否在合理范围 (≥3页) |

**展示方式：**
- 百分制评分 + 等级标签（优秀 ≥85 / 良好 ≥70 / 一般 ≥60 / 需优化 <60）
- 文档列表增加"质量"列，低分项红色标记

### 3.10 操作审计日志 (P2)

| 字段 | 说明 |
|------|------|
| id | 自增主键 |
| timestamp | 操作时间 |
| action | 入库/出库/启用/禁用/删除/编辑 |
| target_type | knowledge_base / document / chunk |
| target_id | 知识库ID / source / chunk_id |
| operator | 操作人（未来接认证系统） |
| detail | JSON 格式的操作详情 |
| result | success / failed |
| error_message | 失败原因 |

**存储：** PostgreSQL `audit_logs` 表

**前端展示：** 知识库详情页底部"操作历史"时间线

### 3.11 智能提醒 (P3)

| 提醒类型 | 触发条件 | 展示方式 |
|----------|---------|---------|
| 文档碎片化 | 切片数 > 同类均值 2 倍 | 页面顶部告警条 |
| 区域标签缺失 | region_code = "000000" 且入库 > 7 天 | 表格行高亮黄色 |
| 入库失败 | 返回码非 0 | Toast 通知 + 列表置顶 |
| 模型离线 | 连续 3 次健康检查失败 | 状态栏变红 |

### 3.12 知识库快照与恢复 (P3)

| 编号 | 功能 | 描述 |
|------|------|------|
| SNAP-01 | 创建快照 | 记录当前切片数和文档列表的快照 |
| SNAP-02 | 快照列表 | 展示历史快照（时间、文档数、切片数） |
| SNAP-03 | 恢复快照 | 删除增量切片，恢复到快照状态 |
| SNAP-04 | 克隆知识库 | 完整复制一个知识库到新 ID（仅复制元数据，向量重新计算） |

### 3.13 导出报告 (P3)

| 编号 | 功能 | 描述 |
|------|------|------|
| EXPORT-01 | PDF 报告 | 知识库文档列表 + 切片统计 + 质量评估 + 入库记录 |
| EXPORT-02 | CSV 导出 | 文档名、切片数、入库时间、状态、地区、标签、质量评分 |
| EXPORT-03 | 定时报告 | 配置周报/月报自动生成 |

## 四、数据模型设计

### 4.1 新增表：知识库元数据

```sql
CREATE TABLE knowledge_bases (
    id          VARCHAR(32)  PRIMARY KEY,
    name        VARCHAR(200) NOT NULL,
    description TEXT,
    is_active   BOOLEAN      DEFAULT TRUE,
    created_at  TIMESTAMP    DEFAULT NOW(),
    updated_at  TIMESTAMP    DEFAULT NOW()
);
```

### 4.2 新增表：操作审计日志

```sql
CREATE TABLE audit_logs (
    id            SERIAL PRIMARY KEY,
    timestamp     TIMESTAMP DEFAULT NOW(),
    action        VARCHAR(50) NOT NULL,
    target_type   VARCHAR(50) NOT NULL,
    target_id     VARCHAR(100) NOT NULL,
    detail        JSONB,
    result        VARCHAR(20) DEFAULT 'success',
    error_message TEXT
);
```

### 4.3 扩展现有表：c_metadata 字段变更

```json
{
  "source": "job_id",
  "filename": "原始中文文件名",
  "type": "child_chunk",
  "recall_context": "父级块完整上下文",
  "chunk_id": "文件名_p0_c0",

  "enabled": true,              // 🆕 启用/禁用
  "knowledge_base_id": "kb_default",  // 🆕 归属知识库
  "tags": ["预算", "2026"],      // 🆕 自定义标签
  "quality_score": 85,          // 🆕 质量评分(0-100)
  "region_code": "1301000",
  "region_name": "石家庄市",     // 🆕 冗余存储，避免每次联表
  "created_at": 1234567890.123,
  "updated_at": 1234567890.123   // 🆕 最后更新时间
}
```

### 4.4 新增表：知识库快照

```sql
CREATE TABLE kb_snapshots (
    id              VARCHAR(32) PRIMARY KEY,
    knowledge_base_id VARCHAR(32) NOT NULL REFERENCES knowledge_bases(id),
    name            VARCHAR(200),
    doc_count       INTEGER,
    chunk_count     INTEGER,
    doc_list        JSONB,
    created_at      TIMESTAMP DEFAULT NOW()
);
```

## 八、非功能需求

### 8.1 性能要求

| 指标 | 目标 |
|------|------|
| 检索测试台响应 | < 2 秒 (Top-10) |
| 编辑操作响应 | < 500ms |
| 仪表盘数据加载 | < 3 秒 |
| 批量操作（50文档） | < 10 秒 |

### 8.2 兼容性

- 浏览器: Chrome 80+, Edge 80+, Firefox 75+
- 后端: Python 3.10+
- 数据库: PostgreSQL 14+ with pgvector 0.5+

- API 操作需记录审计日志
- 检索接口需验证 region_code 权限（后续接入认证）
- 敏感操作（删除知识库）需二次确认
